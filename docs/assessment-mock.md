# 査定支援モック

既存Next.jsサイトの商談用フロントモックです。

| パス | デモの流れ |
| --- | --- |
| `/assessment-mock/manager` | 社員を選択 → データを収集・整理 → 実績と根拠リンク → 社員別の面談メモ |
| `/assessment-mock/explanation` | 社員選択 → 実績と過去履歴から評価案 → 根拠確認 → 編集・上長確認 |
| `/assessment-mock/sources/[id]` | 根拠リンクから開く元記録のプレビュー |

`/assessment-mock` に一覧ページはありません。振り返りページは削除済みです。

## 自動収集のデモ

Slack・メール・スプレッドシートから収集した架空の業務記録を、実績・日付・本人の担当範囲とともに表示します。根拠リンクは元記録のサンプル画面を別タブで開きます。実サービスのURLやアカウントへの接続はありません。

記録の収集と事実の確認は別です。上長確認済みの記録と本人の投稿を分け、未確認の頻度や効果を成果として断定しません。評価・処遇は上長が判断します。

## 起動・検証

```bash
npm ci
npm run dev
npm run test
npx eslint app/assessment-mock test/assessment-*.test.tsx
npx tsc --noEmit
npm run build
```

起動後 `/assessment-mock/manager` を開いてください。既存Vercelプロジェクト `corporate` へ公開します。

## 範囲

- フロントのみ。実際の生成AI、外部データ収集、認証、DBには接続しません。
- 評価案は、社員別の過去目標と今回の確認済み記録を照合するデモ専用ルールで表示します。履歴は架空データです。
- 評価案の編集・上長確認・チェック状態は再読み込みで消えます。
- 全ページnoindexです。
- 補足情報は開閉式です。参考：[NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)。

## 評価案の表示

社員ごとの架空の評価履歴を2期分用意し、直近の目標と今回の記録を対応付けます。目標の対応記録が上長確認済みの場合のみ「記録で確認」と表示し、不足・本人投稿のみの場合は「要確認」とします。総合区分はデモ専用ルールであり、実際の査定制度の判定や学習済みモデルではありません。

評価案・短い理由・根拠リンクを最初に表示し、履歴・比較・編集欄は開閉式です。社員別の編集と確認状態は画面内で保持します。面談準備と評価案は同じ社員データを使用し、相互リンクで社員を引き継ぎます。

面談準備のタブと面談ポイント確認件数は削除し、実績・根拠を直接表示します。面談メモは収集前から入力でき、社員切替・再収集でも保持します。再読み込みや画面移動で初期化されます。
